* LiveCodeBench: all 3 models are suspected of contamination, gemma4-31b-fp8 most clearly. GLM-5.2/5.3 were corrected twice: (1) normalized to the correct denominator of 200 problems (glm5.3 had skipped 6 problems that crashed during grading instead of counting them as failures; the baseline had skipped 1); (2) re-verified by running the model-generated code against the real test cases, which uncovered a race condition in the parallel grader that caused some problems to be assigned another problem's test cases and wrongly graded "fail": glm5.3 2/5 failed problems affected (189→191), baseline 1/78 (121→122, 77 genuine failures). gemma4-31b-fp8 uses a 198/1055 sample, raw 186/198 (93.94%), and after fixing the same race condition (9/12 raw failures actually pass) → 98.48% (195/198) — and reaches an absolute 100% on "hard" difficulty despite almost completely failing SWE-bench Pro/DeepSWE, the strongest contamination signal observed across the 3 campaigns. None of the 3 LiveCodeBench numbers should be treated as final — rerun with a release_version newer than each model's training cutoff. See each run's README.md and the memory note lcb-grading-race-condition-bug.md for details.
SciCode: glm5.2/glm5.3 matching on sub-step (40.35%) is a genuine statistical coincidence, verified problem by problem (13/30 problems have different results between the 2 runs) — not a bug or caching. gemma4-31b-fp8 (41.23%, n=30/65) is slightly higher, within the noise margin given the small n.
BFCL: mean of Non-Live Overall and Live Overall (AST), 13/13 single-turn categories (multi-turn/memory/web-search/format-sensitivity not run) for all 3 models.
DeepSWE / SWE-bench Pro (gemma4-31b-fp8): the clearest agentic capability gap — almost complete failure (SWE-bench Pro 22.5%, DeepSWE 0.0%) while on single-turn knowledge/QA/function-calling benchmarks (MMLU-Pro, BFCL, SciCode) it is only slightly lower than or on par with the 2 GLM baselines. See gemma4-31b-fp8-full-results.md and jobs/gemma4-31b-fp8/README.md.
